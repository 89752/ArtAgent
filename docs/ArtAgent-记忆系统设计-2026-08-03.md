# ArtAgent 记忆系统设计（2026-08-03）

> 定位：对标成熟 Agent 记忆系统（Mem0 / LangMem / Letta(MemGPT) / Zep / ChatGPT·Claude 记忆），
> 解决评估暴露的三个硬伤：写入不可靠、记忆污染无隔离、更新语义缺失。

## 1. 现状与问题（评估证据）

当前实现：`src/memory/store.py`（preferences 表 + upsert/load/list/delete）、
`src/memory/collections.py`（收藏表）、`tools/memory.py`（remember/recall/forget，
硬编码 DEFAULT_USER）、图节点 `load_memory`/`save_memory`、LangGraph MemorySaver 线程历史。

多轮评估（2026-08-03，2/6）暴露：

| 问题 | 证据 | 根因 |
|---|---|---|
| 写入不可靠 | mt-001 用户说"记住我特别喜欢莫奈的睡莲系列"，工具链里**没有 remember 调用**，口头确认了事 | 记忆写入依赖模型自觉，无强制路径 |
| 记忆污染/无隔离 | mt-001 第二轮把上一轮评估写入的"卡拉瓦乔偏好"当成用户真实偏好回答 | 全部用户/线程共享 `web_user` 偏好表，无 namespace；评估未清场 |
| 更新语义缺失 | mt-005 偏好漂移（巴洛克→洛可可）未正确覆盖 | 无冲突检测/版本/来源，纯 upsert 无法表达"这是新偏好，旧的作废" |
| 读取无精度 | mt-001 读到无关旧记忆并采信 | load_memory 全量塞入，无相关性/新鲜度/来源过滤 |

## 2. 设计目标与原则

1. **写得到**：用户明确要求记忆时，系统必须落库（工具强制 + 守卫校验），禁止"口头假装记住"；
2. **读得准**：注入的记忆必须与当前问题相关、有来源与时间，可追溯、可怀疑；
3. **分得清**：user / thread / scope 三层隔离，评估与生产互不污染；
4. **变得了**：偏好漂移 = 显式覆盖（保留版本历史），不静默合并；
5. **删得净**：用户可查看/删除自己的记忆，删除后不再注入；
6. **可评估**：记忆写入率、读取命中率、漂移正确率、隔离正确率进入评测体系。

## 3. 对标模型（借鉴点）

| 系统 | 核心模式 | 本项目借鉴 |
|---|---|---|
| Mem0 | 记忆即"事实条目"，add/update/delete + 语义检索 + 冲突处理（LLM 判断合并/覆盖） | 事实条目化、检索评分、冲突解析 |
| LangMem / LangGraph Store | 命名空间（user/thread）+ `remember`/`search` 工具 + BaseStore 持久化 | namespace 隔离、记忆工具即标准工具 |
| Letta / MemGPT | 核心记忆（常驻上下文小块）+ 档案记忆（向量库）+ 回忆记忆（历史），系统级自管理 | 记忆分层：core block 常驻、语义/情景外置 |
| Zep | 时序知识图谱：实体/关系/事实随事件演化，自动处理关系变更 | 事实带时间线、变更留历史 |
| ChatGPT / Claude | 异步抽取记忆为短句，相关时注入，用户可见可删 | 用户可见性、按需注入 |

## 4. 总体架构（四层）

```text
L1 工作记忆   LangGraph 线程上下文（MemorySaver + 窗口/摘要）
      │  必要时压缩
L2 语义记忆   memory_items：用户偏好/事实/画像（结构化 + 向量）
      │  检索注入（相关性 + 新鲜度 + 重要性）
L3 情景记忆   memory_episodes：交互摘要（时间线，供"上次我们聊过…"）
      │  事件回流
L4 外部知识   文档/收藏（已有 collections / user_pdf_*，不属于用户记忆但可引用）
```

设计原则：**L2 是主体**（评估暴露的问题都在这里）；L1 复用现有线程机制并修复 thread 语义；
L3 作为 Phase 2 增量；L4 保持现状。

## 5. 数据模型

### 5.1 `memory_items`（语义记忆主表，替代/兼容 preferences）

```sql
CREATE TABLE memory_items (
  id            TEXT PRIMARY KEY,            -- uuid
  user_id       TEXT NOT NULL,               -- 隔离键：真实用户 / eval-test
  thread_id     TEXT,                        -- 可空：线程级记忆
  scope         TEXT NOT NULL DEFAULT 'user',-- user | thread | agent
  kind          TEXT NOT NULL,               -- preference | fact | profile | event
  content       TEXT NOT NULL,               -- 单条陈述式记忆："用户偏好莫奈睡莲系列"
  entity        TEXT,                        -- 关键实体（莫奈/睡莲），用于检索与冲突
  embedding     BLOB,                        -- content 向量（bge-m3 复用）
  importance    REAL NOT NULL DEFAULT 0.5,   -- 0-1，注入排序用
  source        TEXT NOT NULL,               -- user_explicit | extracted | eval
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL,
  version       INTEGER NOT NULL DEFAULT 1,
  superseded_by TEXT,                        -- 漂移覆盖：指向新条目 id
  deleted_at    TEXT                         -- 软删除
);
```

### 5.2 `memory_events`（审计，Phase 1 即建）

```sql
CREATE TABLE memory_events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id TEXT NOT NULL,
  item_id TEXT,
  action TEXT NOT NULL,     -- create | update | supersede | recall | delete
  detail TEXT,              -- 来源上下文摘要/工具参数
  created_at TEXT NOT NULL
);
```

### 5.3 兼容层

`preferences` 表保留为视图/迁移源：`load_preferences` 改读 `memory_items WHERE kind='preference'`；
`collections` 表不动（收藏是用户产物而非记忆，但跨轮状态校验继续用它）。

## 6. 写入流程（解决"写不到"）

```text
用户表达记忆意图
  └─ 强制路径：Agent 必须调用 remember(content, kind='preference')
       ├─ 守卫（general_tools）：AI 消息声明"已记住"但本轮无 remember 调用 → 拒绝通过并提示重试
       └─ 落库前处理：
            ├─ 规范化：LLM 抽取为单条陈述（"用户偏好：莫奈睡莲系列"）
            ├─ 冲突检测：同 user+entity+kind 查旧条目
            │     ├─ 语义相同 → 更新时间戳，不新增
            │     └─ 语义冲突（漂移）→ 新建条目，旧条目 superseded_by=新 id（保留版本）
            └─ 审计：memory_events(action=create/update/supersede)
```

关键点：
- **写入必须走工具**：`remember` 是唯一写入口；`save_memory` 节点只做摘要/情景记忆，不再直接写偏好；
- **漂移显式化**：mt-005 的"巴洛克→洛可可"应产生"覆盖"事件，而不是并存两条冲突偏好；
- **来源可追溯**：`source=user_explicit / extracted / eval`，评估数据永远不混入生产（见隔离）。

## 7. 读取/注入流程（解决"读不准"）

`load_memory` 节点重构为"记忆检索器"：

1. 输入：当前问题（rewrite 后）+ 线程最近 2 轮；
2. 检索：`semantic_search` 复用 bge-m3 对 memory_items 打分，按 `score = α·相似度 + β·新鲜度 + γ·重要性` 排序；
3. 过滤：只取 `deleted_at IS NULL`、scope 匹配（user/thread）、与当前 query 相关（相似度阈值）；
4. 注入：拼成 system prompt 的 `## Memory` 块（**token 预算上限，如 800 token**），每条带
   `（来源：用户明确/自动抽取 · 时间：3 天前）`；
5. 不注入：无关记忆不进上下文——这是 mt-001 读到"卡拉瓦乔"的根治。

读取侧还要加一条纪律：**记忆是偏好不是事实**。对用户画像类记忆，回答时可引用但注明"根据你之前的偏好"；
对不确定的旧记忆，允许向用户确认，而不是自信地用错。

## 8. 更新 / 遗忘 / 隔离

### 更新
- 同义合并：同 entity+kind 语义相同 → 更新时间戳与重要性；
- 漂移覆盖：语义冲突 → 新建 + supersede（旧条目保留可追溯，但不再参与检索）；
- 工具：`remember(content, kind)` 内部完成以上逻辑，Agent 无需感知。

### 遗忘
- `forget(entity)`：软删除 + `memory_events(action=delete)`；
- 用户可见：`/api/memory` 列表 + 单项删除（复用现有 `delete_preference` 的 API 形态）；
- 容量上限：单用户条目数/总 token 预算超限时，按重要性+新鲜度淘汰（软删除），记审计。

### 隔离（解决"污染"）
- **namespace = (user_id, thread_id, scope)**，所有读写强制带 user_id；
- 工具层 `DEFAULT_USER` 改为环境可配置（`MEMORY_USER_ID`），**评估用 `eval-test` 身份**；
- 评估脚本：多轮/记忆用例前清空 `eval-test` 的 memory_items + collections（已有 `_cleanup_state`，补"用例前清场"）；
- 生产多用户（platform/users 已有 user 体系）天然隔离。

## 9. 工具与图节点改造

| 组件 | 现状 | 改造 |
|---|---|---|
| `remember` | 写 preferences（硬编码用户） | 走 memory_items，支持 kind/scope，内部冲突解析 |
| `recall` | 读 preferences | 语义检索 + 排序 + token 预算，返回带来源/时间 |
| `forget` | 删除 preferences | 软删除 + 审计 |
| `load_memory` | 全量注入 | 检索注入 + Memory block 模板 + 预算 |
| `save_memory` | 汇总/存偏好 | 只做情景摘要（Phase 2），不再越权写偏好 |
| `general_tools` 守卫 | 只查 schema/超时 | 增加"记忆声明必须有 remember 调用"校验 |
| 评估 | 共享 web_user | 独立 eval-test 身份 + 用例前清场 + 记忆指标 |

## 10. 可观测与评估（记忆指标进评测体系）

新增 `eval/sets/memory_golden.json`（或升级 multi_turn）：

| 指标 | 口径 | 门槛 |
|---|---|---|
| 写入率 | 用户明确"记住X"后 memory_items 落库比例（mt-001 类） | ≥95% |
| 读取命中率 | 相关记忆在注入块中且被正确引用 | ≥90% |
| 漂移正确率 | 偏好变更后旧值被 supersede、新值生效 | 100% |
| 隔离正确率 | eval-test 写入在生产 user 不可见 | 100% |
| 污染率 | 注入块中出现无关/过期记忆的比例 | ≤5% |

方法论对标：Mem2ActBench（记忆是否被主动用于工具动作）、LoCoMo/LongMemEval（长对话记忆检索）。

## 11. 成本与性能

- 写入：每次 remember 一次 embedding（~40ms）+ 一次 LLM 规范化/冲突判断（可合并进 remember 工具调用，约 1 次 LLM）；
- 读取：每轮一次 memory 检索（bge-m3 编码 + SQLite/向量 top-k，~50ms），注入 ≤800 token；
- 审计写：纯 SQLite，可忽略；
- 目标：单轮记忆开销 ≤1 次额外 LLM 调用 + 100ms 检索。

## 13. 风险与不做什么

- **不把记忆当事实**：记忆条目是"用户说过/偏好"，不是画作知识；知识类检索仍走 RAG；
- **不自动记住一切**：默认只记用户显式表达 + 高置信偏好（自动抽取默认关闭，Phase 2 再评估开放）；
- **不混评估数据**：eval 身份写入永远隔离，报告标注来源；
- **不做复杂图谱**：先用条目+实体+时间线（Zep 式图谱留待有明确场景再做）。

## 16. 自动抽取层（Phase 1.5，2026-08-04 ✅ 已实现）

### 16.1 市场成熟 Agent 的做法（调研结论）

用户没有说"记住/喜欢"时，成熟产品不是不记，而是**在后台自动抽取 + 按需注入**：

| 系统 | 机制 | 对本项目的启示 |
|---|---|---|
| ChatGPT 记忆 | 显式记忆 + **Dreaming 后台自动整理**（2025→2026 两代演进）：对话自然推进后异步抽短句、合并/覆盖、相关时注入 | 自动抽取不需要用户触发；节流 + 异步 |
| Claude memory tool | 模型在工作中**主动调用记忆工具**存储所学内容（含对话中的隐含偏好） | 抽取动作可以挂在现有工具链，而非独立系统 |
| Mem0 | `add()` 后管线 **Extract → Consolidate → Retrieve**；对每条历史做 ADD/UPDATE/DELETE/NOOP 分类，不存原文 | 动作分类（NOOP 过滤）比"全记"更接近真实 |
| LangMem | 显式 remember/search + **CreateMemoryManager / 后台 memory manager agent** 自动抽取（ReflectionExecutor 延迟去重） | 抽取可延迟到回合后，避免阻塞主流程 |
| Zep | 纯自动抽取实体/关系/事实，建时序知识图谱 | 事实带时间线、变更留历史（本项目的 supersede 同思路） |

**共同纪律**：不是全记（NOOP 占比很高）；新旧冲突走 UPDATE/覆盖；异步后台执行；
敏感信息保护；用户可见可删。用户没明说时，抽取的是"稳定事实/高置信偏好"，
一次任务、寒暄、过程性信息一律丢弃。

### 16.2 实现（代码在 `src/memory/extract.py`）

- **开关**：`MEMORY_AUTO_EXTRACT=1` 开启（**默认 0**，验证后再开）；
  `MEMORY_EXTRACT_INTERVAL=N`（默认 2）控制每 N 轮抽取一次；
- **流程**：`save_memory` 节点到期后把最近 6 条用户/助手消息交给 LLM，
  输出 `[{action: ADD|UPDATE|DELETE|NOOP, kind, entity, content, importance}]`；
  落库 `source='extracted'`，冲突沿用 `add_memory` 的同义合并/漂移覆盖；
- **身份**：`get_memory_user_id()`（与 remember/recall 一致，评估自动隔离）；
- **纪律**：只抽稳定事实/偏好；正则 + 提示词双重过滤敏感信息（证件/密码/
  银行卡/验证码等）；LLM 失败/畸形输出安全 NOOP 且推进节流计数；
- **用户可见可删**：抽取条目与其他记忆同源展示（`/api/memory`），可单项删除。

## 17. 多轮回归修复（2026-08-04）

### mt-002：改写过度压缩导致追问误判

- 现象：`介绍一下莫奈` → `他晚年怎么了？`，第二轮被 `ask_user` 以"信息不足"
  反问，未回答莫奈晚年；
- 根因：`rewrite_split` 的 LLM 压缩把追问压成 <6 字（如"莫奈晚年"），
  `_info_gap` 的 `len(q) < 6` 长度启发式据此误判；
- 修复：`rewrite_and_split` 增加"过度压缩回退原文"守卫；`ask_user` 的信息缺口
  判定改用 `original_user_query`（改写前的原始问题）；回归用例已补

### 19.1 容量 / 淘汰策略
