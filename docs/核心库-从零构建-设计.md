# ArtAgent 核心库从零构建设计（替代 SemArt 成为默认数据源）

> 状态：设计定稿（2026-08-02，经用户决策：放弃以 SemArt 为核心，从零建库）
> 前置：`docs/数据扩充-设计.md` 为 AIC 试点记录（本设计继承其管道，扩大为多源核心库）。

## 1. 决策与定位

- **SemArt 不再是核心/默认数据源，但作为"描述源"融入核心库**（2026-08-02 决策）：
  SemArt 的 21,384 条艺术评论文本是高质量的描述层素材，与 AIC/Wikidata 一样
  作为普通来源并入 core（normalize_core.py 的 --semart 路线），
  一举解决描述稀疏问题；其独立 semart 数据源保留为回滚/对照路径，
  eval 基线（意图分类 / Recall@5）暂时仍以其为参照。
- **新核心库**：`dataset_id="core"`，三层架构（Wikidata 骨干 + 博物馆作品源 + 描述组装），
  目标规模 1–2 万幅"有描述、可语义检索"的作品 + 知识层表（画家/流派/博物馆）。
- **长尾不本地化**：超过核心集的作品元数据由 Stage 7 实时 API（museum_search）承担。

## 2. 三层架构

```
① 骨干层 Wikidata：画家（生卒/国籍/流派/师承/别名）、流派运动、博物馆、系列关系
   —— 提供稳定 QID、跨源链接、知识本体（timeline/recommendation 的骨架）
② 作品层 博物馆开放数据：AIC / Rijksmuseum / NGA / MET / Cleveland / Smithsonian
   —— 权威的标题、年代、材质、尺寸、图片、馆藏
③ 描述层 描述组装（决定语义检索/推荐质量）：
   馆藏展签文本（Rijksmuseum plaque / AIC description / CMA）
   → Wikipedia 词条导语 → Wikidata 短描述 → LLM 补全（仅知名作品，抽样核验）
```

## 3. 统一 Schema

### 3.1 core_artworks（作品表）

| 列 | 说明 |
|---|---|
| `artwork_id` | 优先 Wikidata QID；无则 `{source}:{object_id}` |
| `title` | 标题（en） |
| `title_aliases` | 别名（多语言/曾用名） |
| `artist_qid` / `artist_name` | 画家 QID + 显示名 |
| `collection_qid` / `collection_name` | 馆藏博物馆 |
| `location` | 现藏地（博物馆 · 城市） |
| `inception` / `year` / `year_bucket` | 创作年代（过滤 + timeline 轴） |
| `material` / `medium` | 材质 |
| `genre` / `movement` | 题材/流派（genre 为作品级，movement 由画家继承） |
| `series` | 所属系列（莫奈干草堆等） |
| `description` | **唯一进向量的字段**（组装后） |
| `image_url` | Commons/博物馆图 URL |
| `license` | 版权记录 |
| `dimensions_raw` / `width_cm` / `height_cm` | 尺寸 |
| `source_api` / `provenance` | 来源与溯源 |
| `dedup_key` | `artist\|title\|year` 小写归一化，跨源去重 |

### 3.2 core_artists（画家表，知识层）

`artist_qid / name / aliases / birth / death / nationality / movement / influenced_by / image_url / biography(可选)`

### 3.3 core_movements（流派表）

`movement_qid / name / period_start / period_end / description / notable_artists`

## 4. Wikidata 采集方案（2026-08-02 实测）

**可行性实测**：
- 画家（`P106=画家` + `P135=流派` + `P18=图`）：**6,275 位**，查询秒级；
- 按博物馆查询带图绘画（title/artist/image/date）：可用，字段质量好；
- **全表 COUNT / GROUP BY 聚合会 504 超时** → 采集一律用"非聚合 + LIMIT/OFFSET 流式分页"，
  禁止 COUNT 探测（需要统计时用本地 CSV 统计）。

**SPARQL 模板（scripts/harvest_wikidata.py）**：

画家：
```sparql
SELECT ?artist ?artistLabel ?birth ?death ?natLabel ?movLabel ?img WHERE {
  ?artist wdt:P31 wd:Q5 ; wdt:P106 wd:Q1028181 ; wdt:P135 ?mov ; wdt:P18 ?img .
  OPTIONAL { ?artist wdt:P569 ?birth }  OPTIONAL { ?artist wdt:P570 ?death }
  OPTIONAL { ?artist wdt:P27 ?nat }
  SERVICE wikibase:label { bd:serviceParam wikibase:language "en,zh". }
} LIMIT 50000 OFFSET {offset}
```

作品（逐个博物馆拉取，避免聚合超时）：
```sparql
SELECT ?w ?wLabel ?artistLabel ?collLabel ?inception ?materialLabel ?genreLabel
       ?img ?locLabel ?seriesLabel ?desc WHERE {
  VALUES ?c { wd:Q{collectionId} }
  ?w wdt:P31 wd:Q3305213 ; wdt:P170 ?artist ; wdt:P195 ?c ; wdt:P18 ?img .
  OPTIONAL { ?w wdt:P571 ?inception }  OPTIONAL { ?w wdt:P186 ?material }
  OPTIONAL { ?w wdt:P136 ?genre }      OPTIONAL { ?w wdt:P276 ?loc }
  OPTIONAL { ?w wdt:P179 ?series }
  OPTIONAL { ?w schema:description ?desc . FILTER(LANG(?desc) = "en") }
  SERVICE wikibase:label { bd:serviceParam wikibase:language "en,zh". }
} LIMIT 5000 OFFSET {offset}
```

**博物馆 QID 清单（首期）**：Louvre Q19675 / MET Q160236 / Rijksmuseum Q190804 /
National Gallery London Q180788 / NGA Washington Q214867 / AIC Q239303 / Prado Q160112 /
Uffizi Q51252 / MoMA Q188740 / Tate Q430682 / Hermitage Q132783。

**描述组装顺序**（harvest 之后单独步骤）：
1. 馆藏展签文本（AIC `description` 已入库；Rijksmuseum plaque 需接；CMA description）；
2. Wikipedia EN 词条导语（通过 QID 的 sitelink 查 `w/api.php?action=query&prop=extracts&exintro`，
   只对"知名作品 + 仍无描述"做，控制调用量）；
3. Wikidata `schema:description`（免费短描述，兜底）；
4. LLM 补全（最后手段，抽样人工核验）。

## 5. 博物馆作品源清单与映射

| 源 | 规模 | key | 描述 | 状态 |
|---|---|---|---|---|
| SemArt（描述源） | 21,384 | 无 | 全部（评论体长文） | ✅ 管道已建（并入 normalize_core） |
| AIC | 3,900 带图绘画 | 无 | ~1,259 条有描述 | ✅ 管道已建（data/extended/aic.csv） |
| Rijksmuseum | ~70 万对象 | 免费 key | plaque 展签文本（EN/NL） | 待接 |
| NGA | 13 万+ | 无（离线 CSV） | provenance 文本 | 待接（下载最快） |
| MET | ~47 万 | 无 | 弱 | 只收 PD 图子集，描述靠补 |
| Cleveland | ~6.8 万 | 无 | 部分描述 + provenance | 待接 |
| Smithsonian | 300 万+ | 免费 key | 部分描述 | 美国艺术补充 |

SemArt 映射：AUTHOR 倒序名归一化（"GOGH, Vincent van"→"Vincent van GOGH"，dedup_key
与 Wikidata/AIC 显示序对齐）；TYPE→genre（题材）；SCHOOL→school（民族画派）；
DATE 提取首个 4 位年；TIMEFRAME→year_bucket；DESCRIPTION→description；
IMAGE_FILE→image_url（本地文件，前端 _thumb_data_uri 走 SemArt/Images/ 渲染）。

映射沿用 `docs/数据扩充-设计.md` §3 的角色化规则（entity=artist / axis=year_bucket /
description / image），各源只是不同的 fetch loader。

## 6. 入库管道

```
harvest_wikidata.py（画家表 + 各馆作品表，SPARQL 流式）
  + 各博物馆 fetch（AIC 已建，其余按 §5 补 loader）
  → normalize：统一 core schema + 派生 year_bucket / dedup_key
  → 合并去重（dedup_key；Wikidata 行优先保留 QID）
  → assemble：描述组装（§4）
  → index：有描述子集 BGE 向量化 → Chroma collection "core"
  → register：dataset_id="core"（df 表全量 + collection 向量子集）
```

## 7. 运行时改造清单（SemArt 降级）

1. `src/retrieval/base.py`：`RetrievalSource` 加 `"core"`（`"extended"` 已加，可改名/合并）；
2. `src/retrieval/structured_retriever.py`：把 `semart` 特判泛化为"内置数据集注册表"
   （`core` 懒注册；`semart` 仍可注册但不再默认）；
3. `src/retrieval/hybrid.py`：`get_hybrid_retriever` 默认 `active_dataset="core"`；
4. `web/service.py::datasets()`：默认项改为 core，SemArt 移入历史区（或隐藏）；
5. `src/tools/retrieval.py::_format_result`：加 `core` 分支（契约同 semart：
   title/author/date/image_file/description_snippet）；
6. `web/service.py::_thumb_data_uri`：支持 http(s) URL 直通（core 图是 URL）；
7. eval：新库独立评测集（Recall@K 用 core 语料），意图分类集不变；
   基线切换后 SemArt 路径标记 deprecated。

## 8. 验收与里程碑

- **M1**：Wikidata 画家表 + 5 馆作品表采集完成（非聚合分页、无超时），CSV 落盘；
- **M2**：描述组装（AIC 原生 + Wikidata 短描述 + Wikipedia 导语抽样）后，
  有描述率 ≥ 60%，向量化入 core collection；
- **M3**：运行时切换默认源为 core，UI 切换器可见，semart 标记历史；
- **M4**：core 独立评测（意图分类 ≥ 94%、Recall@K 记录基线），
  旧 parity 脚本锁 semart 不再作为唯一尺子；
- 全程纪律：外部 API 显式超时 + 重试；每源 `source_api/provenance` 溯源；跨源去重不丢 QID。
