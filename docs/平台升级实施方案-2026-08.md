# ArtAgent 平台升级实施方案（2026-08）

> 制定日期：2026-08-03 ｜ 依据：`docs/ArtAgent-平台化对标评估-2026-08.md`
> 定位：**垂直 Agent 平台**——把"艺术 Agent"固化为平台第一张王牌模板，而不是做通用平台正面竞争。

---

## 0. 目标与原则

**目标**：把 ArtAgent 从"单域、单用户、高质量 Agent 应用"升级为"可承载多 Agent、多用户、可配置、可发布、可观测、可运维的垂直 Agent 平台"，同时完整保留现有 Agent 内核资产（意图树、多意图并行、工具守卫、记忆、混合检索、评估体系）。

**原则**：
1. 内核不动，只加"外壳"——编排/检索/记忆/评估能力已经是 4/5，平台化的增量全部在工程产品层。
2. 身份与隔离先行——没有用户模型，后面的 API、租户、安全、计费都无从谈起。
3. 应用 = 可配置资产——Agent 的一切（提示词、工具、技能、知识库、MCP 服务器）收敛到 manifest，换领域不再改代码。
4. 兼容优先——所有改动保持旧接口可用（默认 `web_user`），前端 UI 不中断。
5. 分期验收——严格按"一期地基 → 二期可运营 → 三期生态"推进，不一次性铺开。

## 1. 三期路线图

### 一期（4–6 周）：平台地基 —— 本方案当前执行期

| # | 任务 | 交付物 | 验收 |
|---|---|---|---|
| P0-1 | 用户模型与数据隔离 | `users`/`api_keys`/`user_settings` 表；会话、偏好、摘要、文档、向量集合全部按 `user_id` 隔离；级联删除 | 两个用户数据完全不可见、不可串；删除用户级联清空 |
| P0-2 | Agent Manifest + 多 Agent 注册 | `AgentSpec`（JSON/YAML）+ `agents/` 目录 + registry；ArtAgent 固化为内置模板；图编排按 manifest 绑定 system prompt / 工具白名单 / 技能 / MCP | 一个进程注册多个 Agent；新 Agent 不改代码 |
| P0-3 | 公共 API 面 | 业务/渲染解耦（结构化事件流）；OpenAI 兼容 `/v1/chat/completions`（流式+工具调用事件）+ `/v1/models`；开启 OpenAPI 文档 | API 客户端可鉴权流式对话；UI 与 API 共用同一 Agent 内核 |
| P0-4 | MCP 消费侧 | 薄 MCP client 适配器（stdio，可选官方 `mcp` 包）；manifest 声明 `mcp_servers`，第三方工具导入工具带 | 配置的 MCP Server 工具可被 Agent 调用；缺依赖时优雅降级 |

**一期验收总门槛**：两个用户各建一个 Agent 互不可见；第三方 MCP 工具可被 Agent 调用；API 客户端可流式对话；全部纯单测通过。

### 二期（4–6 周）：可运营

- P0-5 任务表与持久执行：`tasks` 表 + 重启扫描 `interrupted` + 重试入口 + 解析信号量 + 请求限流。
- P0-6 可观测性：`request_id` 贯穿日志/SSE/DB；`agent_runs` 表（意图/节点/工具/耗时/上下文体积）；`/api/metrics` 汇总。
- P0-7 安全加固：前端 DOMPurify 或纯文本白名单渲染；上传归属与内容嗅探；外部内容边界（注入防护）；鉴权覆盖 `/api/*`。
- P0-8 部署产物：Dockerfile + docker-compose（api + worker + 卷 + 健康检查）；GitHub Actions（纯单测 + 离线 eval 子集）；配置分级（`ARTAGENT_ENV`）。
- P0-9 评估流水线：扩集（意图≥200/检索≥100/事实≥50）+ LLM-as-judge + CI 门禁 + 👍/👎 反馈闭环。

**验收**：一键 `docker compose up` 起服务；CI 绿了才能合代码；任意一次对话可回放完整决策链与成本。

### 三期（6–10 周）：生态与差异化

- 管理台：Agent 清单编辑（manifest 编辑器）、知识库状态与重解析、用户/会话管理、成本/延迟看板。
- MCP 提供侧：把 ArtAgent 技能发布为 MCP Server；多 Agent 协作（sub-agent / handoff / 审批型 HITL）。
- 模型路由与降级：多供应商 + 健康状态 + TTFT 探测（对话/视觉/嵌入全部降级链）。
- 知识库增强（版本/回滚/chunk 校对/按 KB 隔离）、定时任务、多渠道发布（网页嵌入 SDK / 飞书 / 企微）。
- Stage 7 领域技能包（color_analysis / museum_search / nearby_venues / wiki_lookup）作为平台内置技能包。

## 2. 一期详细设计

### 2.1 P0-1 用户模型与数据隔离

**数据模型**（`data/platform/platform.db`，可用 `ARTAGENT_PLATFORM_DIR` 覆盖）：

```text
users(user_id PK, name, created_at)
api_keys(key PK, user_id, label, created_at)      # 首版静态 token：secrets.token_hex(24)
user_settings(user_id PK, dataset_id)             # 每用户生效数据源，避免全局切换串户
```

**既有存储的归属改造**：

| 存储 | 现状 | 改动 |
|---|---|---|
| `conversations` 表 | 无 `user_id` 列 | `ALTER TABLE` 迁移加列（默认 `web_user`）；全部 CRUD 带 `user_id` 过滤 |
| `preferences` 表 | 已有 `user_id` | 无需迁移；级联删除补接口 |
| `conversation_summary` 表 | 已有 `user_id` 但读取不带 | `load_summary(conversation_id, user_id)` 按用户过滤 |
| `documents` 表 | 无 `user_id` 列 | 迁移加列；`list/get/delete` 按用户过滤；`delete_documents_by_user` 供级联 |
| Chroma `user_pdf_text` / `user_pdf_images` | 元数据无 `user_id` | 入库时写入 `user_id`；检索时强制 `where.user_id`（不是可选） |
| `StructuredTableRetriever` | 全局注册 | 增加 `owner_user_id`；Hybrid 检索跳过非本人表格 |

**级联删除**：`delete_user(user_id)` → 删除 api_keys/settings → 会话/偏好/摘要 → 文档（含 Chroma 向量与上传文件）→ 用户行。

**鉴权（首版）**：`/v1/*` 强制 `Authorization: Bearer <api_key>` 或 `X-API-Key`；`/api/*`（本地 UI）暂保持免鉴权、默认 `web_user`，二期 P0-7 统一加固。用户管理走 `scripts/manage_users.py` 命令行，不开放公网接口。

### 2.2 P0-2 Agent Manifest

`AgentSpec` 字段：

```text
id / name / description / version
system_prompt            # 内联文本，或 "@builtin:artagent"（复用 prompts.SYSTEM_PROMPT），或相对文件路径
model_config             # temperature 等（预留）
tools                    # 非技能工具白名单；null = 全部
skills                   # 技能 id 白名单（skill_<id>）；null = 全部
knowledge_base           # 绑定知识库（预留，默认 core）
memory                   # {enabled, preferences, summary}
guardrails               # 预留：evidence_grounding / cost_bounds / prompt_injection
mcp_servers              # [{name, command, args, env, enabled}]
```

`src/platform/registry.py` 启动加载 `agents/*.json|yaml`；`AgentState.agent_id` 贯穿图执行；`nodes/general.py` 按 agent 构建工具带（含 MCP 工具）与 system prompt。内置模板 `agents/artagent.json` 固化当前艺术 Agent 的全部能力。

### 2.3 P0-3 业务/渲染解耦 + OpenAI 兼容 API

- 新增 `src/platform/events.py`：结构化事件类型 `start / node / intent / tool / answer / done / error`。
- `web/service.py` 抽出共享内核 `_run_graph(...)`：跑图、跟踪步骤、收集工具调用与证据；`stream_answer`（HTML 渲染，前端不动）与 `stream_answer_events`（结构化流）共用内核。
- `src/platform/openai_api.py`：
  - `GET /v1/models`：列出已注册 Agent。
  - `POST /v1/chat/completions`：`model` = agent id；非流式返回 `chat.completion`（含 `artagent` 扩展字段：steps/sources/intent）；流式返回 `chat.completion.chunk`，工具事件映射为合法的 `delta.tool_calls`，结尾 `[DONE]`。
- `api.py` 开启 `/docs` 与 `/redoc`（评估指出 `docs_url=None` 是负分项）。

### 2.4 P0-4 MCP 消费侧

- `src/platform/mcp_client.py`：薄适配器，优先使用官方 `mcp` 包（stdio/HTTP 全传输）；未安装时启用内置零依赖 stdio JSON-RPC 客户端（initialize → tools/list → tools/call），满足最小 MCP 子集。
- Manifest 声明 `mcp_servers` 后，Agent 工具带自动追加 `mcp_<server>_<tool>`，继续走现有工具守卫（`guard.py`）。
- 连接失败不阻断 Agent：日志告警 + 降级为无 MCP 工具。

## 4. 风险与边界（诚实提示）

1. **本会话落地一期核心，不等于一期全部完成**：API Key 轮换/审计、Webhook、速率限制、`agent_runs` 成本归因、前端 DOMPurify 等划入二期。
2. **OpenAI 兼容是"Agent 自带工具执行"模式**：客户端收到工具调用事件是执行轨迹展示，工具由平台执行；若需要客户端接管工具执行（外部 function calling），需二期开放 `stop` 语义与工具回调接口。
3. **YAML manifest 需要 PyYAML**：当前环境未安装，内置模板用 JSON；YAML 加载器在安装 PyYAML 后自动可用（已写入 requirements）。
4. **MCP 官方包未安装**：适配器内置 stdio 降级实现可零依赖工作；HTTP/SSE 传输在官方包安装后可用。
5. **旧数据兼容**：所有迁移默认把存量数据归属 `web_user`，单机自用数据不丢。
