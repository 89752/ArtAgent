### 1.2 对标"成熟 Agent 应用"仍缺的关键项（本方案要解决的）

| # | 差距 | 现状 | 成熟应用基准 |
|---|---|---|---|
| G1 | 反馈闭环 | 无 👍/👎、无原因标签、无反馈数据回流 | ChatGPT/Coze 标配 |
| G2 | 记忆可见可控 | 只能一键清空偏好，用户看不到记住了什么、无法单项删除 | ChatGPT 记忆管理 |
| G3 | 引用不可交互 | sources 已结构化输出，但前端没有可点击引用/证据展开 | Perplexity/NotebookLM |
| G4 | XSS 风险未除 | `static/lib/` 仅 marked.min.js；`marked.parse` 渲染 LLM 输出无 sanitize | 所有成熟产品 |
| G5 | 任务可靠性 | PDF/表格解析仍走 `BackgroundTasks`，进程崩溃即丢，无重试 | 任务表 + 恢复 |
| G6 | 工具执行治理 | 工具无统一超时/重试/出参校验/审计（仅 LLM 调用有超时） | 平台级工具治理 |
| G7 | 并发与限流 | 无解析信号量、无请求限流 | 429 + 并发控制 |
| G8 | 可观测性 | 只有结构化日志；无每轮轨迹表、无成本/延迟指标、无看板 | LangSmith/商业看板 |
| G9 | 模型鲁棒性 | 对话/视觉单模型无降级（仅检索精排有主备接力） | 多供应商降级 |
| G10 | 评估体系 | 样本小（意图 50/检索 25/事实 6）；CI 只跑 3 个测试文件；无答案质量评估；无反馈回流 | 扩集 + 门禁 + judge |
| G11 | 部署形态 | 无 Docker；配置靠 .env 散项 | Docker Compose + 环境分级 |

## 2. 目标定义（O1~O6）

- **O1 稳定性**：连续 30 天运行 0 次任务丢失、0 次进程卡死；kill/断网/超时故障注入全部有兜底
- **O2 体验**：用户可完成 4 个标准动作——点赞/点踩、查看与单项删除记忆、停止生成（已具备，验收回归）、点击引用展开证据
- **O3 质量**：意图分类 ≥96%（200+ 样本）、Recall@5 不回归（≥76%）、事实准确率 ≥95%（50+ 样本）、LLM-as-judge 答案质量 ≥85%
- **O4 安全**：XSS 注入用例全过滤；上传与图片路由无越权访问（既有防穿越保持）
- **O5 运维**：任意一次对话可从记录完整回放；单次成本与延迟可查；`docker compose up` 一键启动
- **O6 工程**：CI 门禁全绿才可合代码；全部 362+ 新增测试通过

## 3. 分阶段实施计划

### 一期：体验闭环与安全（第 1–3 周）

**目标：用户能"点得动、看得见、停得下、问得回"，并且没有已知 XSS 风险。**

| # | 任务 | 关键内容 | 工时 |
|---|---|---|---|
| 1.1 | 反馈闭环 | `feedback` 表（session_id/rating/reason/comment/created_at）+ `POST /api/feedback` + 前端 👍/👎 与原因标签；导出脚本（eval 候选池） | 3d |
| 1.2 | 记忆可见可控 | `GET /api/preferences` 扩展为分项列表（kind/value/weight/updated_at）；`DELETE /api/preferences/{kind}/{value}` 单项删除；前端"Agent 记住了什么"面板 | 2d |
| 1.3 | 引用可交互 | 后端 `done` 事件 sources 已结构化 → 前端将回答中 [N] 渲染为角标，点击展开证据卡（标题/来源/页码/缩略图） | 2d |
| 1.4 | XSS 修复 | `static/lib/` 引入 DOMPurify（本地 vendored）；所有 `marked.parse` 输出先 sanitize；后端渲染路径 escape 审计 | 1d |
| 1.5 | 错误态验收 | 复用已有 422/500 处理器，补齐 LLM 超时/额度/网络错误 → 用户可读文案 + 重试按钮；前端不白屏 | 1d |
| 1.6 | 中止/重生成回归 | 现有 Stop/regenerate 补集成测试（SSE 中途断开、regenerate 替换旧问答） | 0.5d |

**里程碑 M1（第 3 周末）**：4 个标准交互全部可用；XSS 注入用例全过滤；反馈数据入库。

### 二期：可靠性与可观测（第 4–7 周）

**目标：从"能跑"到"敢长期跑、坏了好查"。**

| # | 任务 | 关键内容 | 工时 |
|---|---|---|---|
| 2.1 | 任务化与持久执行 | `tasks` 表 + 状态机（pending/processing/done/failed/interrupted）；PDF/表格解析迁入任务模型；启动时恢复 interrupted；长对话推理登记任务 | 5d |
| 2.2 | 工具执行治理 | 统一工具包装器：超时、重试策略、结果轻量校验、入参/出参/耗时审计；单工具失败降级为错误消息不中断整轮 | 3d |
| 2.3 | 并发与限流 | 解析任务信号量（≤2）；请求级令牌桶限流（429）；SQLite 写队列与连接健康检查 | 2d |
| 2.4 | 可观测性 | `agent_runs` 表（session/意图/节点耗时/工具/上下文体积/成本估算）；`GET /api/metrics`（P50/P95、成本、工具分布、reflection/兜底率）；request_id 贯穿日志 | 4d |
| 2.5 | 模型鲁棒性 | 对话模型主备降级（env 可配）；视觉模型补备；失败自动切换不中断回答 | 2d |

**里程碑 M2（第 7 周末）**：故障注入测试全部有兜底；任意对话可回放；成本/延迟可查。

### 三期：质量闭环与发布（第 8–10 周）

**目标：质量变成机制，运行变成按按钮。**

| # | 任务 | 关键内容 | 工时 |
|---|---|---|---|
| 3.1 | 评估体系扩容 | 意图集 50→200+；检索集 25→100+；事实题 6→50+（SemArt 元数据自动生成 + 人工审核）；工具选择集 ≥30；行为化重复 2→5 次 | 4d |
| 3.2 | LLM-as-judge 答案质量 | 事实性/引用忠实度/完整性三维评分（独立 judge 模型，双跑取均值）；纳入 eval 报告 | 3d |
| 3.3 | 反馈回流闭环 | feedback 表 → 新 eval 候选脚本（每周人工审核入库） | 1d |
| 3.4 | CI 门禁增强 | 纯单测全量 → eval 离线子集（意图/检索，可关 rerank）→ 行为化 nightly；`scripts/regression.ps1` 固化回归命令 | 2d |
| 3.5 | 部署产物 | Dockerfile + docker-compose（api + 卷 + healthcheck）；`.env.example` 补全（模型主备、限流、日志级别） | 3d |

**里程碑 M3（第 10 周末）**：O1–O6 全部达成，发布 v1.0。

## 4. 工作量估算

单人全职：一期 9.5d + 二期 16d + 三期 13d ≈ **39 人日 ≈ 8 周**；加 20% 缓冲 ≈ **9–10 周**。

### 关键路径

- 1.1 反馈闭环 → 3.3 反馈回流（数据模型首版要留 session_id 与原因字段）
- 1.3 引用交互依赖 1.4 XSS 修复（sanitize 先于渲染新交互）
- 2.1 任务化是 2.3 并发控制与 3.5 部署的前置
- 2.4 可观测的字段口径在 2.2 工具审计中定义

### 可并行项

- 1.2 记忆面板与 1.4 XSS 修复互不依赖
- 2.4 与 2.5 可并行
- 3.1 与 3.2 可并行（3.2 用现有 50 条集先跑通，再随 3.1 扩集）

## 7. 范围护栏（明确不做）

- 不做平台层增量：`src/platform/` 接线、/v1 API、多用户隔离、MCP、AgentSpec 扩展——**已有代码保留但不在本方案推进**
- 不做多 Agent 协作、插件市场、可视化工作流编辑器
- 不做移动端、多渠道发布、定时任务
- 不做向量记忆库
- 不引入重型依赖（Redis/消息队列/PostgreSQL 均不引入；DOMPurify 本地化）

## 9. 结语与第一步建议

本方案按"体验 → 可靠 → 质量"三步走，9–10 周把 ArtAgent 打磨为可天天用、敢上线、有质量门禁的成熟 Agent 应用（应用维度综合成熟度 2.7 → 4.2）。平台层代码不受影响、不参与本方案。

**开工前第一件事**：当前工作树有大量未提交改动（含已完成的 Stop/重生成/校验/CI 与未接线的平台层代码），先提交或冻结基线，并跑一遍 `tests/test_web_api.py` + `test_service_render.py` 确认现状全绿；然后从 1.1 反馈闭环开工。
