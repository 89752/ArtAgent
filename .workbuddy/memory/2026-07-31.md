# 2026-07-31

## ArtAgent 2.0 设计方案评估（用户请求：评估能否按步骤开发）

对照真实代码逐条核验了 `Downloads/ArtAgent-2.0-设计方案.md`，结论：**可按步骤开发，但需先补 8 个遗漏点**。

### 核验通过的事实
- 7 工具中 6 个绑 SemArt（general.py GENERAL_TOOLS 确认）；模糊匹配 4 处重复（retrieval/image_lookup/style_comparison/image_analysis）；截断 200/250/300 三处不一；timeline_gather_periods 双重查询；compare_artwork_styles 与 query_painter_knowledge 内藏 LLM 调用——全部属实。
- 外部依赖联网核实：qwen3-vl-embedding（2560维，$0.258/M图）与 tongyi-embedding-vision-plus（1152维，$0.09）均存在；qwen3-rerank 有 OpenAI 兼容端点（gte-rerank-v2 已于 2026-05-30 下线）；MinerU v3.1 起改为 Apache 2.0 自定义协议、Windows/CPU 可用；Met API 免 key（限速 80 req/s，CC0 仅公共领域作品）。

### 发现的关键遗漏（方案未提）
1. **旧 PDF 实验遗产**：`src/data/pdf_loader.py` 是无引用孤儿代码（import fitz，但 PyMuPDF 不在 requirements.txt）；Chroma 里有残留 `user_pdfs` 集合；`data/uploads/` 有 12 个旧会话目录+真实 PDF；`data/index/` 有 faiss.index+metadata.pkl 残留（约49MB）。Stage 1 清理清单应加入。
2. **集成点**：AgentState 需加 `dataset_id` 字段；`web/service.py` stream_answer 的每轮状态重置清单需同步加。
3. README 仍引用已删除的 app.py（Gradio 兜底），requirements.txt 仍列 gradio。
4. MinerU 官方 known issue：艺术图册解析不佳——与项目领域直接相关，双路线设计可对冲但需真实画册验证。
5. MinerU CPU 同步阻塞 100 页 PDF 约 5-10 分钟，Phase 1 同步方案需限页数或提前做 BackgroundTasks。
6. 测试全是真实 API 冒烟测试，重构期应给 access.py 配纯单测；eval "完全一致"验收过严，LLM 有波动，应改"无显著回归"。
7. color_analysis 需 K-means，requirements 无 sklearn（可用 numpy/PIL 实现）。
8. Web UI 不宜作为落地顺序第 8 步整体推进，应拆进 Stage 3/5/6。

工作量粗估：全职约 2 周、兼职 3-4 周（Stage 3 最大头 4-6 天）。
